# Vehicle data, stage 1: Chinese names, Versions, and the 400 px photo door

Included as whole files in `leap_vehicle_data_stage1.zip`. **If you have changed `services/api/src/modules/fitment/routes.js`, `apps/admin-dashboard/src/App.jsx` or `apps/admin-dashboard/src/auth.js` since the project was last shared, do not overwrite them: apply the edits below by hand.** The zip needs the earlier "announcements" zip to be applied first (its `App.jsx` contains that card too). **Run `node db\migrate.js` (or `start-leap.cmd`) and restart the backend afterwards.** Stage 2 (the Excel import) comes next and will need `npm install exceljs` in `services\api`.

## What changes
- **Chinese names:** a NEW brand or model needs its Chinese name (English and Arabic are required as before). Older brands and models keep working and show no Chinese name until one is added with Edit (the Edit dialog now has the field). The brand/model lists and the supplier-facing GET answers carry `nameZh`.
- **Versions:** a new level under each Year. A version has its name and its engine in English, Arabic and Chinese (all six required), seats (a whole number from 1 to 12) and a photo (required when added by hand). The same version name with the same engine cannot be added twice to one year. In the admin portal: Vehicle Data > a brand > a model > each year has a "Versions" control (add, edit, replace the photo, delete). A version without a photo (which the coming Excel import will create) is marked "No photo yet" and has an "Add photo" button.
- **The 400 px photo door:** brand, year and version photos and the CATEGORY photo go through the new `POST /fitment/catalog-image` (admin only; shortest side at least 400 px; bigger is fine; PNG, JPEG or WebP; 10 MB; a cut-off picture is refused). **Every other photo keeps its 800 px door untouched** (`POST /uploads/product-image`: products, hub photos, buyer review photos; and in the admin portal: part photos, product editing, payment methods).
